# 영역 1: 클라우드 네이티브 아키텍처 (Cloud Native Architecture - 16%)

> 클라우드 환경에서 확장 가능하고(Scalable) 장애 복원력(Resilient)을 갖춘 현대적 시스템을 구축하기 위한 기본 철학과 원칙

---

## 1. CNCF가 정의하는 클라우드 네이티브 (Cloud Native Definition)

CNCF의 공식 정의에 따르면, 클라우드 네이티브 기술은 조직이 퍼블릭, 프라이빗, 하이브리드 클라우드와 같은 현대적이고 동적인 환경에서 **확장 가능한(Scalable)** 애플리케이션을 구축하고 실행할 수 있도록 지원합니다.

### 4대 핵심 특성
1. **컨테이너 (Containers)**: 애플리케이션과 그 종속성을 단일 단위로 패키징하여 어디서나 일관된 실행 보장.
2. **서비스 메시 (Service Meshes)**: 마이크로서비스 간의 통신, 보안, 가시성, 트래픽 라우팅을 투명하게 관리.
3. **마이크로서비스 (Microservices)**: 단일 책임을 갖는 작고 독립적으로 배포 가능한 서비스들의 결합.
4. **불변 인프라 (Immutable Infrastructure)**: 서버나 컨테이너를 실행 중에 수정하지 않고, 변경이 필요하면 새 버전으로 교체 배포.
5. **선언적 API (Declarative APIs)**: "무엇을 어떻게 해라(명령형)"가 아니라 "이러한 상태가 되도록 유지하라(선언형)"는 원칙.

## 2. 12-Factor App 방법론 (The Twelve Factors)

현대적인 클라우드 네이티브 SaaS 애플리케이션을 구축하기 위한 표준 가이드라인:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   The Twelve-Factor Methodology                        │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Codebase       : 버전 관리되는 하나의 코드베이스와 다양한 배포      │
│ 2. Dependencies   : 명시적으로 선언되고 격리된 종속성                 │
│ 3. Config         : 환경(운영, 개발)에 따른 설정을 코드에서 분리       │
│ 4. Backing Services: 데이터베이스, 큐 등을 연결된 리소스로 취급        │
│ 5. Build, Release, Run: 빌드, 릴리즈, 실행 단계의 엄격한 분리           │
│ 6. Processes      : 무상태(Stateless) 및 비공유(Share-nothing) 프로세스│
│ 7. Port Binding   : 자체 포함된 포트 바인딩을 통해 서비스 공개         │
│ 8. Concurrency    : 프로세스 모델을 통한 수평 확장(Scale-out)          │
│ 9. Disposability  : 빠른 시작과 우아한 종료(Graceful Shutdown)        │
│ 10. Dev/Prod Parity: 개발, 스테이징, 프로덕션 환경의 일치 유지         │
│ 11. Logs          : 로그를 이벤트 스트림으로 취급                      │
│ 12. Admin Processes: 일회성 관리/운영 작업을 독립된 프로세스로 실행    │
└────────────────────────────────────────────────────────────────────────┘
```

> **시험 빈출 팩터**:
> - **Factor III (Config)**: DB 패스워드나 엔드포인트를 코드에 하드코딩하지 않고 환경 변수(`ConfigMap`, `Secret`)로 주입해야 함.
> - **Factor VI (Processes)**: 프로세스는 상태를 내부에 보관하지 않고, 영속 데이터는 백엔드 저장소(DB, Cache)에 위임해야 함.
> - **Factor IX (Disposability)**: 컨테이너는 SIGTERM 신호를 수신했을 때 신속하고 우아하게 종료(Graceful shutdown)될 수 있어야 함.

## 3. 모놀리스 vs 마이크로서비스 아키텍처

```
[ Monolith ]                          [ Microservices ]
┌─────────────────────────┐           ┌──────────┐  ┌──────────┐
│ UI / Presentation       │           │ User Svc │  │ Order Svc│
├─────────────────────────┤           └────┬─────┘  └─────┬────┘
│ Business Logic (All)    │                │              │
├─────────────────────────┤           ─────┼──────────────┼─────
│ Shared Database Layer   │                ▼              ▼
└─────────────────────────┘           ┌──────────┐  ┌──────────┐
                                      │ User DB  │  │ Order DB │
                                      └──────────┘  └──────────┘
```

| 특성 | 모놀리식 (Monolithic) | 마이크로서비스 (Microservices) |
| :--- | :--- | :--- |
| **코드베이스** | 단일 대규모 레포지토리 | 서비스별 독립 레포지토리/디렉토리 |
| **배포 단위** | 전체 시스템 일괄 배포 | 서비스별 독립적 무중단 배포 |
| **장애 격리** | 한 모듈의 메모리 누수가 전체 다운 유발 | 장애가 특정 서비스에 격리됨 (서킷 브레이커) |
| **기술 스택** | 단일 언어 및 프레임워크 종속 | 서비스별 폴리글랏(Polyglot) 선택 가능 |
| **데이터베이스** | 단일 통합 DB (트랜잭션 ACID 용이) | 서비스별 전용 DB (Eventual Consistency) |
| **복잡성** | 비즈니스 로직 복잡성 | 네트워크 통신 및 분산 트랜잭션 복잡성 |

## 4. 서버리스 & 이벤트 기반 아키텍처 (Serverless & Event-Driven)

### 서버리스 (Serverless / FaaS)
- 인프라(서버) 관리를 클라우드 제공자나 플랫폼에 완전히 위임.
- **Scale-to-Zero (0으로 축소)**: 요청이 없을 때는 인스턴스를 0개로 유지하여 비용 절감.
- **Cold Start (콜드 스타트)**: 유휴 상태에서 첫 요청이 유입될 때 컨테이너를 프로비저닝하면서 발생하는 초기 지연.
- **대표 CNCF 프로젝트**: **Knative** (Kubernetes 기반 서버리스 플랫폼), **OpenFaaS**.

### 이벤트 기반 아키텍처 (Event-Driven)
- 서비스 간 통신을 동기식 HTTP REST 호출 대신 비동기 이벤트 메시지로 처리.
- 생산자(Producer)와 소비자(Consumer) 간의 완전한 결합 해제(Decoupling).
- **대표 CNCF 프로젝트**: **CloudEvents** (이벤트 데이터 표준 규격), **NATS** (경량 메시징 시스템), **Strimzi** (Kafka on K8s).

## 5. CNCF 성숙도 모델 (Maturity Levels)

CNCF는 프로젝트의 생태계 채택도, 커뮤니티 건강성, 보안 감사 결과에 따라 3단계로 분류합니다:

1. **Sandbox (샌드박스)**:
   - 초기 단계의 실험적이고 유망한 프로젝트.
   - 예: Kwasm, KubeArmor, Carina.
2. **Incubating (인큐베이팅)**:
   - 프로덕션 환경에서 채택되기 시작한 성숙한 단계, 최소 3개 이상의 독립 기업 기여.
   - 예: Dapr, Thanos, Cilium (최근 Graduated 승격), KEDA.
3. **Graduated (졸업 / 정식 인증)**:
   - 엔터프라이즈 환경에서 널리 검증되었으며 최고의 거버넌스와 보안 감사를 통과한 핵심 프로젝트.
   - **대표 프로젝트**:
     - 컨테이너 오케스트레이션: **Kubernetes**
     - 모니터링: **Prometheus**
     - 서비스 프록시: **Envoy**
     - 컨테이너 런타임: **containerd**
     - DNS 서비스: **CoreDNS**
     - 로깅: **Fluentd**
     - 분산 추적: **Jaeger**
     - 컨테이너 레지스트리: **Harbor**
     - 패키지 관리: **Helm**
     - GitOps 지속적 배포: **Argo CD**
     - 정책 엔진: **Open Policy Agent (OPA)**
